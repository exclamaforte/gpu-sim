# gpu-sim-6kp item 0c: real-driver-mapped witness

## Differential probe (specified by PI)
Probe: cudaDeviceCanAccessPeer (single call, no allocation, driver topology query,
       on the committed growth list as an unimplemented dependency) under
       LD_PRELOAD=libfakegpu.so with LD_DEBUG=files, then /proc/self/maps dump.

LD_DEBUG=files output:
  file=libcuda.so.1 [0]; dynamically loaded by libcudart.so.13
  file=libcuda.so.1 [0]; generating link map
  calling init: /usr/lib/libcuda.so.1

/proc/self/maps (post-call):
  /usr/lib/libcuda.so.615.78.08 mapped (r--p, r-xp, r--p segments)

=> OUTCOME (b): libcuda.so.1 APPEARS. The runtime DOES reach the real driver
   internally when a non-covered API is called. 0c option (i) applies plainly:
   real driver for memory/topology/NVML, identity from the shim.

## Counts
- cudart exports 442 cuda* runtime symbols
- shim provides 67
- 375 are not covered (any call outside the shim's set routes to the real
  driver through libcudart's own dlopen/dlsym/dlvsym path)

## NCCL run exercised set
LD_DEBUG=bindings on probe_nccl4: only 2 shim exports bound:
  - cudaGetDeviceCount
  - cudaSetDevice
Both are in the shim's 67. The NCCL run never calls a non-covered API, so the
real driver is never reached internally. "not mapped in the NCCL run" is
EXPLAINED, not merely observed: the exercised set stays inside the shim's 67.

## Retiring sentence
The shim covers 67 of cudart's 442 runtime entry points; identity is served by
the shim; any entry point outside that set routes to the real driver through
libcudart's own dlopen path. True whichever way a probe lands.

## Conclusion
Device count/identity come from the shim. Memory/topology/NVML come from the
real driver when a non-covered API is called (demonstrated: cudaDeviceCanAccessPeer
loads libcuda.so.615.78.08). The NCCL run exercises only covered APIs, so the
real driver is not mapped in that run. A broader workload calling non-covered
APIs would load the real driver.
