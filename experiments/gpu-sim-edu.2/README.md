# gpu-sim-edu.2 — the lab runtime is untracked, and `git clean -fd` would delete all of it

## What is present and what is absent

| named in the bead | state |
|---|---|
| `.lab/inbox/` | **present** — `implementer.md`, `pi.md`, `reviewer.md`, `archive/` |
| `.lab/prompts/` | **present** — one file per role |
| `.lab/labd.log` | absent |
| `.lab/pid` | absent |
| `.lab/queue_check.py` | absent |

Also present: all five role sockets (`implementer`, `labd`, `pi`, `reviewer`,
`tmux`) and `labd-state.json`.

**The shape of this is a migration, not a deletion.** The loose file-based
runtime is gone and the socket + state-file runtime is intact — those are two
generations of the same design, not a hole where something used to be.

## It is not a git casualty

`.lab` was **never tracked** (`git log --all -- .lab` is empty), and no tracked
file is recorded deleted. So no git operation can account for the absence, and
none of my worktree churn this session targeted a top-level `.lab` file — every
removal I made was scoped under `.lab/wt/`.

## The real hazard, which is worse

```
$ git clean -fdn
Would remove .lab/tmux.sock, .lab/labd.sock, .lab/pi.sock, .lab/reviewer.sock,
            .lab/implementer.sock, .lab/labd-state.json, .lab/prompts, .lab/inbox
```

**A single `git clean -fd` from the repo root would delete the entire live lab** —
every role socket, the daemon's state, all inboxes and all prompts. The trap is
that these files are *untracked*, so they do not make the tree dirty and no
cleanliness check can see them.

Which makes this a hole in the guard **I wrote for `gpu-sim-edu.1.1` hours ago**:
it refuses CWD-scoped destructive git only when tracked files are modified, so it
*permitted* `git clean -fd` precisely when the tree was clean — which is the
condition under which clean does maximum damage. Verified against the real board:
the guard now exits 2.

## The fix

`lab_runtime_paths_would_be_removed()` asks git (`git clean -fdn`, a **dry
run**) what a command would take, rather than guessing from the command text.
Any such deletion is refused with the paths named, ahead of the cleanliness
branch, because the whole point is that a clean tree is the dangerous one.

Scope note: this branch carries the guard **as amended by this bead**. The
`gpu-sim-edu.1.1` branch is unmerged; this version supersedes it and should be
the one that lands.

## One measurement error worth recording

My first `inventory.py` resolved the repo root to *its own worktree*, which has
no `.lab/`. It therefore reported "no lab runtime at risk" — the most dangerous
possible direction for this particular number to be wrong in. It now resolves
the **main** worktree via `git rev-parse --git-common-dir`. Same slip as
measuring a pipeline's exit code through `head` earlier today: the number was
taken from the wrong process.
