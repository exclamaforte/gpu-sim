# gpu-sim-u2o.15 — a reopened bead may not be re-closed with nothing behind it

The finding this bead records: all 60 beads under epic `gpu-sim-u2o` were marked
closed within ~18 hours without a single CUDA kernel being compiled, executed
and timed on the real 5090. No individual field was a lie. The mechanism was a
**close that asserted completion with nothing behind it.**

So the acceptance is made mechanical: a bead reopened by this audit, when closed
again, must carry a pointer a reader can go and look at.

## What counts as concrete

| counts | does not count |
|---|---|
| a repo path to an **artifact** that exists (`experiments/…`, `runs/…`, `.jsonl`, `.ckpt`, …) | a **source file** — a script existing is not a measurement |
| a **resolvable** commit hash | a commit this repository does not have |
| a **result figure** — `1.02x`, `0.0082 ms`, `264 rows` | a spec parameter (`N=1024`), a bare count, `0.0s` |

## Won't-fix is a different kind of close

`gpu-sim-u2o.16` closed as *won't-fix*. That is **not** the failure this bead
targets, and demanding a measurement artifact from a bead that deliberately
declined the work would train people to attach fake dataset paths to won't-fix
closures. Those are reported separately, never as violations.

Intent is read from `close_reason` when present, and otherwise from the
**opening** of the notes. Scanning the whole text classified by accident:
`gpu-sim-u2o.17.1` cites u2o.16 as context while its own close is a genuine
completion, and it was nearly swept in.

## Live result

72 beads carry `fab-audit-reopened`; 12 are closed. **3 are violations**:

- `gpu-sim-u2o.6.8` — `close_reason` is literally `Closed`; the trace it cites
  is not in master.
- `gpu-sim-u2o.17.1` — cites only a capture script.
- `gpu-sim-u2o.17.2` — cites nothing.

8 pass with a real commit or a real figure. `gpu-sim-u2o.16` is excluded as
won't-fix.

**This is a finding, not a cleanup.** Those three closes assert completion with
no checkable artifact behind them, which is the shape of the original failure.
I have not edited them — this script reports and never modifies a bead, because
a check that can edit the thing it checks is not a check.
